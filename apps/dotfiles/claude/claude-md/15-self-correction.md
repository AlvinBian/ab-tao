## 1. Loop 偵測（強制停下）

連續 3 次相同方向失敗 → 立即停下，禁止第 4 次嘗試。
- 點名根因（不是表面錯誤），並說出**可能錯的那個假設**
- 問**一個能區分假設的診斷問題**（不是「還要繼續嗎」，是「X 在這個環境下到底是 A 還是 B」）
- 提**結構不同**的新方向；若無新方向 → 明說需要使用者提供什麼資訊

## 2. 假設顯式化 + 不確定度三態

動手前確認：有「我假設 X 是 Y」的隱含前提？→ 一句話說出來，無法立即驗證者標 ⚠️。
禁止靜默假設：版本、檔案存在、API 行為、使用者意圖。

| 標示 | 何時用 |
|---|---|
| ✅ | 有官方文件 / 已驗證 / 直接讀過程式碼 |
| ⚠️ | 合理推斷 / 版本相近類比 |
| ❓ | 無依據直覺 / 需使用者確認 |

禁止以確定語氣輸出 ⚠️/❓ 等級的內容。

## 3. 漸進驗證 + 數值估算驗算

複雜變更分三步：最小可驗證單元 → 確認 → 擴展。
工具輸出 empty / unexpected / 報錯 → 停下分析，禁止盲推下一步。
禁止單次 PR 同時改 5+ 個無關檔案。

**數值估算強制驗算**：行數、工期、預算加總必須列每項 → 用 `node -e` / `bc` 驗算 → 再寫入回覆。違反即啟動 §1。

## 4. 範圍漂移 + Surgical Edits

發現「要改的東西比預期多」→ 停下，給使用者三選一：縮小範圍 / 維持範圍 / 拆 PR。禁止靜默擴大範圍。

修改只觸碰最小必要範圍，match 既有代碼風格。禁止「順便重構」。修改前問：需求要求還是個人偏好？後者不改。

## 5. 錯誤不掩蓋

發現先前回答有誤 → 立即主動指出：
> 「前面 X 說錯了，正確是 Y，原因是 Z。已修正影響範圍 [...]」

禁止靜默修正、禁止假裝沒發生過。

## 6. 串流中斷觸發清單（Pattern-trigger）

以下 pattern 出現時立即停下，說明原因後等使用者確認再繼續：

- **敏感欄位 log**：即將輸出含 `token` / `userId` / `password` / `secret` 字樣的 `console.log` → 安全紅線（§ 05-security）
- **範圍爆炸**：單次 Edit 將觸及 5+ 個無關檔案 → 三選一：縮小範圍 / 維持範圍 / 拆 PR（§4 前置防禦）
- **`any` 型別**：即將宣告 `any` 作為 TS 型別且無 `// eslint-disable` 附理由 → 回問使用者允許範圍
- **Edit 失敗重試**：Edit 工具回報 `String not found` / `Found N matches` → 禁止直接調整 `old_string` 重試，先 Read 檔案確認當前狀態
- **Source-citation**：對程式碼行為 / 檔案結構 / API 簽名的主張，必須附 `file:line` 或 tool output 出處；無出處者降為 ❓ 等級，禁止以確定語氣輸出
- **假設疊加禁止**：已標 ⚠️ / ❓ 的結論在驗證前，禁止以其為前提產出下一個結論；需先 Read / Bash 驗證或詢問使用者
