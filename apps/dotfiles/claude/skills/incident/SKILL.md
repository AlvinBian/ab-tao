# Incident 處理流程

## Step 1 — 定級

| 級別 | 說明 |
|------|------|
| 🔴 P0 | 核心功能完全不可用，影響所有用戶 |
| 🟡 P1 | 重要功能降級，影響部分用戶 |
| 🟢 P2 | 非核心異常，有替代方案 |

確認：哪個服務？影響範圍？開始時間？

## Step 2 — 診斷

```bash
curl -I https://{service}/health
git log --oneline -10
# 看錯誤日誌（最近 30 分鐘）
```

列出 3 個最可能原因，從最可能開始排查。

## Step 3 — 止血（先恢復再找原因）

1. **回滾** — 最近有部署就先回滾
2. **繞過** — 關功能開關、切備援
3. **擴容** — 負載問題先擴 instance
4. **重啟** — 最後手段

## Step 4 — 溝通模板

**初始通報**（5 分鐘內）：
```
🔴 [P{級別}] {服務} 異常
影響：{範圍} | 開始：{時間} | 狀態：調查中
處理人：@{你} | 下次更新：15 分鐘後
```

**恢復通報**：
```
✅ [已恢復] {服務} 恢復正常
耗時：{X} 分鐘 | 根因：{簡述} | 後續：{預防措施}
```

## Step 5 — 復盤（24-48h 內）

```markdown
# 事故復盤：{標題}

## 時間線
| 時間 | 事件 | 執行人 |
|------|------|--------|

## 根因分析（5 Why）
1. 為什麼？→ 2. 為什麼？→ ...

## 行動項目
| 項目 | 負責人 | 截止日 |
|------|--------|--------|

## 經驗教訓
- 做得好：{保留}
- 可改進：{改進點}
```
